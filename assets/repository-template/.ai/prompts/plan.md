# Plan 阶段提示模板

将 `{{TASK_PATH}}` 替换为实际任务路径后使用。

```text
你现在处于 PLAN 阶段。请先阅读 AGENTS.md、.ai/profile.md、.ai/conventions.md、项目上下文文件，以及 {{TASK_PATH}}/task.md。

只进行只读调查，不修改产品代码。把计划写入 {{TASK_PATH}}/plan.md，并确保包含：
1. 当前 delivery_level、architecture_style 及本任务适用的额外门槛；
2. 对用户目标、用户场景、非目标和成功标准的复述；
3. 明确区分用户目标、用户提出的方案及其属性（候选方案、强制约束或无）；
4. 当前实现与相关约束；缺陷任务需说明根因及证据；
5. 可选方案、推荐方案、关键取舍和被放弃方案；
6. 预计修改的文件/模块及每项原因；
7. 业务、接口、数据、兼容性、安全、性能和运维影响；
8. 执行策略：默认 `single`；只有至少两个边界清晰、可独立交付的工作流并行能明显改善速度或质量时才选择 `parallel`，有共享写入或前置依赖时选择 `coordinated`；
9. 若拆分，写明每个工作流的交付结果、依赖、互斥写入边界和主 Agent 集成点。优先并行只读调查、测试和评审，不为 Subagent 额外创建任务目录；
10. 分层测试计划；
11. 风险、缓解措施和可执行回滚方案；
12. 未知项、假设和需要确认的问题。

计划完成后，将 task.md 的 status 更新为 PLANNED。若任务需要人工批准，停止实现并请求确认；不得提前修改产品代码。
```
