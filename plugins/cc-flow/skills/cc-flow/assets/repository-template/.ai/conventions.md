# AI 软件研发协议

## 1. 适用范围

用于功能开发、修改、优化、修复及测试/配置/依赖/数据结构变更。只读问答、调研、报告、状态查询和独立文档不生成流程记录。常规 merge/rebase/cherry-pick、发布与部署执行不进入流程；需要语义性代码或配置修改时才恢复开发流程。以上均不扩大远程写入或生产权限。

明确调用 CC Flow 表示采用本协议，不表示强制完整流程。保留用户要求、局部仓库规则和安全约束；发现冲突先说明，不静默降低项目门槛。

## 2. 按风险选择记录方式

- **Light：** 范围小、低风险、容易验证和回退，即使涉及多个文件。简述目标与改动，实施、针对性测试、检查差异、总结；不创建任务目录，不为记录活动更新进度。
- **Compact：** 普通功能默认模式。仅一个 task.md 记录目标验收、方案依据及基线、验证结果。无需五份文档或逐阶段提示模板。
- **Full：** 复杂任务、跨仓库协作或涉及迁移、权限、支付、安全、生产数据及重大兼容性的高风险任务。使用独立 task/plan/test/result/review 文档；高风险计划及回滚必须人工批准。

不按修改文件数机械升级。已有任务沿用原格式；风险上升时先升级 Full，保留 ID 和原有证据，补充完整模板并使用协议 v4，不重复建任务。项目特定的更严格要求仍有效。

## 3. 按需读取与基线

读取适用规则、相关代码和测试；项目目标、架构、业务、profile 和 workspace 仅在涉及时加载。不预读全部上下文、不扫描历史、不重复读取本轮已加载且未改变的内容。仅 Full 按当前阶段需要读取 prompts。

开工或中断恢复时检查工作区、分支、HEAD、上游及目标集成分支，从项目约定或 PR 确认目标，不猜测 main。fetch 相关引用后分别比较上游和目标；与上游同步不代表包含目标最新代码。干净且仅落后上游时按约定快进；脏工作区、分叉或落后目标时保留现场，确认安全同步方案。不得自动 reset、强推或 stash。fetch 失败须披露基线未验证并取得继续的同意。本地无远程记 N/A。基线只记录一次：Light 在总结，Compact 在 task.md，Full 在 plan.md。

## 4. 决策与实现

只询问会实质改变范围、行为或验收的未知项，最多 1～3 个简短问题。区分用户目标和候选实现，明确缺陷或已批准方案无需产品访谈。

重要方案引用代码、测试或测量证据，先选择最小可行改动；抽象、依赖或架构层必须对应简单方案无法满足的已确认要求。“未来可能扩展”不是充分理由。证据不足标为假设，不为填表虚构方案。

新增前依次考虑：项目已有实现与惯例、标准库/框架能力、已有依赖、成熟第三方库、自定义实现。找到合适实现即停止无收益调研，不强行复用不兼容语义。新依赖需确认兼容、维护、安全、许可证和运行成本；不为简单行为引入沉重依赖。

遵循 profile 的交付级别与现有架构，默认 standard + existing，不擅自改档案或迁移架构。enterprise 按实际影响补充性能、安全、恢复等验证；DDD 不等于堆目录和类型。

普通任务先给简短计划；明确授权自主实施时可记录 approval: not_required 及依据，否则按项目约定确认。高风险必须 approved。保护无关改动，范围或风险明显变化先重新确认。

默认单 agent，不为满足流程额外启动评审 agent。确需并行且工具/授权允许时限定独立交付及写入范围，主 agent 整合证据，不为临时 agent 建任务。

## 5. 测试、评审和完成

减文档不减验证。实际执行相关复现、目标测试、必要回归、静态检查及构建；安全/迁移/性能等按风险选择。检查真实 diff，包括正确性、边界、兼容、安全、重复实现与不必要复杂度。

只记录一次命令、结果和简短失败摘要，完整日志放 CI/制品。未运行项说明原因与残余风险，不把未执行写成通过。修复后重新验证受影响路径，不必重复运行未受影响且证据仍有效的检查。

Compact 创建使用 .ai/scripts/ai-task-start.sh <slug> "<title>" [owner]；Full 使用同一命令并设置 CC_FLOW_TASK_MODE=full。新目录为 .ai/tasks/YYYY/MM/DD/HHMMSS-slug/，ID 仍为 YYYY-MM-DD-HHMMSS-slug，旧路径继续有效，不自动迁移。

Compact 的 status 使用 DRAFT/PLANNED/IMPLEMENTING/TESTING/VERIFIED/DONE；test_status 与 review_status 仅在真实验证后设 passed。只有验收满足、必要测试通过、关键评审问题解决、适用文档已更新且未知项如实披露后才能 DONE。Full 在独立 test.md/review.md 保存证据，协议 v1–v4 继续兼容。

只校验当前任务：ai-task-check.sh <任务目录>；--all 仅用于显式全量审计，不在每次开发运行。脚本只检查记录结构，不证明测试质量或审批真实性。

## 6. 文档维护

普通任务所有证据只放 task.md；Full 按职责分文件，引用而不复述。仅当持久事实变化时更新项目文档：目标→project、边界→architecture、业务→business、长期决策→decisions、阶段/风险→progress、使用方式→README/API/运行手册。

不为每个任务刷新所有文档，不写无变化清单，不把聊天和日志复制入 .ai。progress 保持当前快照，不追加日记。历史按需检索；不自动迁移、删除或重写旧任务。不得记录凭证或生产敏感数据。
